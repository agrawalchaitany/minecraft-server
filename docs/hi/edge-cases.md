# <img src="../assets/icons/edge-cases.svg" width="28" height="28" alt=""> असामान्य स्थितियाँ

असामान्य स्थितियों में सर्वर कैसे व्यवहार करता है। **परखा गया** चिह्नित प्रविष्टियाँ एक असली सर्वर पर दोहराई गईं और दिखाया गया व्यवहार देखा गया।

## कॉन्फ़िगरेशन की गलतियाँ

| स्थिति | व्यवहार | |
|---|---|---|
| `EULA`, `TRUE` नहीं है | शुरू होने से मना करता है और स्वीकार करने का तरीका बताता है | परखा गया |
| `RCON_PASSWORD` खाली छोड़ा गया | `/data/.rcon-password` में एक रैंडम पासवर्ड बनाता है, जो रीस्टार्ट पर और बैकअप कंटेनर में भी इस्तेमाल होता है | परखा गया |
| `RCON_PASSWORD` पुराना प्लेसहोल्डर | शुरू होने से मना करता है | परखा गया |
| `RCON_PASSWORD` में backslash या किनारों पर स्पेस | शुरू होने से मना करता है। `server.properties` उसे चुपचाप बदल देता, जिससे सुरक्षित सेव टूट जाते। | परखा गया |
| `MEMORY=2GB` (गलत प्रारूप) | शुरू होने से मना करता है: "must look like 2G or 1536M" | परखा गया |
| `MEMORY`, `CONTAINER_MEMORY` की अनुमति से ज़्यादा | मेमोरी खत्म होने के kill-loop के बजाय, शुरू होने से मना करता है और बताता है कौन-सा `CONTAINER_MEMORY` सेट करें | परखा गया |
| `WATCHDOG_INTERVAL=1m` | शुरू होने से मना करता है: सेकंड की पूर्ण संख्या होनी चाहिए | परखा गया |
| ऑटो-अपडेट चालू होने पर `PLUGIN_UPDATE_TIME=25:00` | ऑटो-अपडेट के चुपचाप न चलने के बजाय, शुरू होने से मना करता है | परखा गया |
| `BACKUP_INTERVAL=abc` | लगातार बैकअप लेने के बजाय, backup कंटेनर error के साथ रुक जाता है | परखा गया |
| `BACKUP_KEEP=0` | नए बैकअप समेत हर बैकअप मिटाने के बजाय, बैकअप मना कर दिया जाता है | परखा गया |
| `MC_VERSION=latest` के साथ `PAPER_BUILD` सेट | बिल्ड रुक जाता है: बिल्ड नंबर केवल सटीक संस्करण के लिए मायने रखते हैं | परखा गया |
| `.env` Windows line endings के साथ सेव | संस्करण पढ़ते समय `make` उन्हें हटा देता है; सुरक्षित रहने के लिए `.env` को LF endings के साथ सेव करें | |
| `.env` बदला पर `make restart` चलाया | पुरानी सेटिंग्स बनी रहती हैं; `make restart` `.env` फिर से नहीं पढ़ता। `make up` इस्तेमाल करें। | |
| accent वाले अक्षर, दूसरी लिपियाँ या इमोजी वाला `MOTD` | `\uXXXX` escapes के रूप में लिखा जाता है, ताकि हर Minecraft संस्करण उसे सही दिखाए | परखा गया |
| `enable-status=false` (सर्वर सूचियों से छिपा) | Health check RCON पर लौट आता है; सर्वर healthy रहता है | परखा गया |
| `server.properties` में `server-ip` सेट | शुरुआत पर खाली कर दिया जाता है; Docker के अंदर सर्वर को सभी इंटरफ़ेस पर सुनना होता है | |

## Minecraft संस्करण

| स्थिति | व्यवहार | |
|---|---|---|
| `MC_VERSION` मौजूद नहीं (`9.9`) | `make` रुक जाता है: उपलब्ध नहीं, `make versions` चलाएँ | परखा गया |
| `MC_VERSION` बहुत पुराना (`1.16.5`) | `make` रुक जाता है: 1.17 या नया सपोर्ट है | परखा गया |
| ऐसा संस्करण जिसके केवल beta Paper बिल्ड हों | `make` रुक जाता है: अभी कोई stable बिल्ड नहीं | |
| `latest` नए Minecraft रिलीज़ पर चला जाता है | केवल इमेज दोबारा बनने पर होता है। अचानक बदलाव से बचने के लिए `MC_VERSION` तय करें। | |
| `MC_VERSION` बढ़ाया | दुनिया का बैकअप, फिर अपग्रेड; प्लगइन्स फिर से तय | परखा गया |
| `MC_VERSION` घटाया | निर्देशों के साथ शुरू होने से मना करता है (डाउनग्रेड सुरक्षा) | परखा गया |
| नए संस्करण का बैकअप रिस्टोर किया | अगली शुरुआत पर डाउनग्रेड सुरक्षा उसे मना कर देती है | |
| Minecraft संस्करण के लिए `JAVA_VERSION` बहुत पुराना | `make` ज़रूरी न्यूनतम Java बताकर रुक जाता है | |
| पुराने `MC_VERSION` के साथ सीधे `docker compose up --build` | बिल्ड "Build with 'make up'" के साथ रुक जाता है; सीधा Compose डिफ़ॉल्ट रूप से Java 25 लेता है | |

## बैकअप और रिस्टोर

| स्थिति | व्यवहार | |
|---|---|---|
| हाथ से और तय बैकअप एक ही पल में | एक के बाद एक चलते हैं (साझा लॉक), ताकि बैकअप के बीच autosave फिर कभी चालू न हो | परखा गया |
| डिस्क में पर्याप्त जगह नहीं | संदेश में आकार बताकर बैकअप मना किया जाता है; सर्वर सुरक्षित रूप से चलता रहता है | परखा गया |
| बैकअप बीच में रुका (कंटेनर मारा गया) | केवल एक छिपी `.partial` फ़ाइल बचती है, और अगला बैकअप उसे हटा देता है। पूरे बैकअप कभी अधूरे नहीं होते। | |
| लिखने के बाद आर्काइव खराब | `gzip -t` से पकड़ा जाता है, हटाया जाता है, और पुराने बैकअप बने रहते हैं | |
| एक ही सेकंड में दो बैकअप | दूसरे को ओवरराइट करने के बजाय एक अनोखा प्रत्यय मिलता है | |
| तय बैकअप के दौरान सर्वर बंद | बैकअप सेव रोके बिना आगे बढ़ता है (कुछ लिखा नहीं जा रहा) | |
| गलत फ़ाइल नाम के साथ `make restore` | कुछ भी छूने से पहले रुक जाता है; सर्वर चलता रहता है | परखा गया |
| खराब फ़ाइल के साथ `make restore` | कुछ भी छूने से पहले रुक जाता है (`gzip -t`) | |
| रिस्टोर के दौरान निकालना विफल (डिस्क भरी) | मौजूदा डेटा अछूता रहता है, क्योंकि निकालना पहले staging फ़ोल्डर में होता है | |
| किसी कारण सर्वर अब भी चलते हुए रिस्टोर | मना कर दिया जाता है | |

## प्लगइन्स

| स्थिति | व्यवहार | |
|---|---|---|
| प्लगइन साइट कहती है कोई संस्करण आपके Minecraft को सपोर्ट करता है, पर उसे नया Java चाहिए | jar से पकड़ा जाता है; काम करने वाला सबसे नया संस्करण इस्तेमाल होता है | परखा गया |
| इस सर्वर पर कोई संस्करण काम नहीं करता | कारण और `JAVA_VERSION` संकेत के साथ छोड़ा जाता है; लोड न हो सकने वाली इंस्टॉल कॉपी हटा दी जाती है | |
| कोई dependency साइट पर घोषित नहीं पर `plugin.yml` में है | Hangar या Modrinth पर नाम से ढूँढी जाती है, और केवल तभी स्वीकार होती है जब jar का प्लगइन नाम मेल खाए | |
| कोई dependency कहीं नहीं मिलती | उसका नाम बताती चेतावनी; सर्वर फिर भी शुरू होता है | |
| एक ही प्लगइन Modrinth और Hangar दोनों से सूचीबद्ध | पहला रखा जाता है, दूसरा छोड़ा जाता है, ताकि Paper को कभी डुप्लिकेट न दिखें | |
| प्लगइन हाथ से भी इंस्टॉल है | प्रबंधित कॉपी छोड़ दी जाती है | |
| प्रोजेक्ट नाम में टाइपो, या मिटाया गया प्रोजेक्ट | चेतावनी; बाकी प्लगइन्स पर असर नहीं | परखा गया |
| शुरुआत के दौरान Modrinth या Hangar बंद | चेतावनी; इंस्टॉल संस्करण बने रहते हैं; अगली शुरुआत पर फिर कोशिश | |
| एक साथ दो प्लगइन अपडेट | दूसरा "already running" के साथ मना कर दिया जाता है | परखा गया |
| स्टेज किए प्लगइन लागू करते समय कंटेनर रुका | लागू करने का चरण दोहराने में सुरक्षित है और अगली शुरुआत पर पूरा होता है | |
| `plugins.txt` byte-order mark या Windows line endings के साथ सेव | संभाल लिया जाता है | |
| `plugins.txt` गायब | प्लगइन्स जैसे हैं वैसे ही छोड़ दिए जाते हैं (कुछ अनइंस्टॉल नहीं होता) | |
| `plugins.txt` से सभी लाइनें हटाईं | हर प्रबंधित प्लगइन अनइंस्टॉल होता है; हाथ से इंस्टॉल jar बने रहते हैं | |

## खिलाड़ी और मोड

| स्थिति | व्यवहार | |
|---|---|---|
| `Steve` के मौजूद रहते ऑफ़लाइन खिलाड़ी `steve` के रूप में जुड़ता है | अस्वीकृत: "already taken, log in as exactly Steve" | परखा गया |
| स्पेस, डैश, accent या डॉट वाला ऑफ़लाइन नाम | नियम समझाते हुए अस्वीकृत | परखा गया |
| मौजूदा खिलाड़ियों के साथ ऑनलाइन → ऑफ़लाइन | बैकअप के बाद डेटा ऑफ़लाइन ID पर ले जाया जाता है | परखा गया |
| ऑफ़लाइन → ऑनलाइन, खिलाड़ी के पास अकाउंट नहीं | बाद में वापस बदलने के लिए उसका डेटा ऑफ़लाइन ID के तहत रखा जाता है | परखा गया |
| Mojang तक न पहुँच पाने पर ऑफ़लाइन → ऑनलाइन | सर्वर शुरू नहीं होता (डेटा बँटने से रोकता है); Docker फिर कोशिश करता है | |
| खिलाड़ी का डेटा दोनों ID के तहत | नई फ़ाइल रखी जाती है; पुरानी `player-migration-conflicts/` में जाती है | परखा गया |
| Geyser/Floodgate से Bedrock खिलाड़ी (`.Name`) | यूज़रनेम नियमों द्वारा अस्वीकृत; `ENFORCE_USERNAME_RULES=false` सेट करें | |

## चलते समय

| स्थिति | व्यवहार | |
|---|---|---|
| सर्वर प्रोसेस क्रैश (`kill -9`) | Docker उसे फिर शुरू करता है; कुछ सेकंड में फिर healthy | परखा गया |
| सर्वर जम जाता है पर प्रोसेस ज़िंदा रहता है | लगभग 5 मिनट तक जवाब न मिलने पर watchdog उसे फिर शुरू करता है | |
| बहुत धीमी पहली शुरुआत (दुनिया बनना) | watchdog पहले जवाब का इंतज़ार करता है; health check 5 मिनट देता है | |
| Java की मेमोरी खत्म | साफ़ बंद होता है और Docker उसे फिर शुरू करता है | |
| खेल में `/stop` लिखा | सेव करके रुकता है; Docker उसे फिर शुरू करता है (बंद रखने के लिए `make down`) | |
| बहुत बड़ी दुनिया 2 मिनट में सेव नहीं हो पाती | `STOP_TIMEOUT` बढ़ाएँ | |
| होस्ट पोर्ट 25565 पहले से उपयोग में | `make up` "port is already allocated" के साथ विफल; `SERVER_PORT` सेट करें | |
| होस्ट रीबूट | Docker शुरू होने पर कंटेनर वापस आ जाते हैं | |

## ज्ञात सीमाएँ

- केवल Paper पर Minecraft: Java Edition 1.17 और नया।
- प्लगइन्स के लिए केवल Modrinth और Hangar अपने आप खोजे जाते हैं।
- खिलाड़ी UUID के तहत रखा गया प्लगइन डेटा ऑनलाइन और ऑफ़लाइन मोड के बीच माइग्रेट नहीं होता।
- `make update-plugins`, `make backup` और `make console` के लिए सर्वर कंटेनर का चलना ज़रूरी है।
- संस्करण तय करने के लिए `make` को Docker से `eclipse-temurin:25-jdk` (एक बार) pull करने देना होता है।
