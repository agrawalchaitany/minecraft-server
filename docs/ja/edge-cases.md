# <img src="../assets/icons/edge-cases.svg" width="28" height="28" alt=""> エッジケース

珍しい状況でサーバーがどう動くかをまとめています。**テスト済み**と書かれた項目は、実際のサーバーで再現し、記載どおりの動作を確認したものです。

## 設定のミス

| 状況 | 動作 | |
|---|---|---|
| `EULA` が `TRUE` でない | 起動を拒否し、同意する方法を説明 | テスト済み |
| `RCON_PASSWORD` が仮の値のまま | 起動を拒否 | テスト済み |
| `RCON_PASSWORD` にバックスラッシュや前後のスペースがある | 起動を拒否。`server.properties` が値を黙って変えてしまい、安全な保存が壊れるため。 | テスト済み |
| `MEMORY=2GB`（形式の誤り） | 起動を拒否: "must look like 2G or 1536M" | テスト済み |
| `MEMORY` が `CONTAINER_MEMORY` の許容量を超える | メモリ不足の強制終了ループではなく、起動を拒否して設定すべき `CONTAINER_MEMORY` を提示 | テスト済み |
| `WATCHDOG_INTERVAL=1m` | 起動を拒否: 秒数を整数で指定する必要がある | テスト済み |
| 自動更新が有効で `PLUGIN_UPDATE_TIME=25:00` | 自動更新が黙って動かなくなるのではなく、起動を拒否 | テスト済み |
| `BACKUP_INTERVAL=abc` | バックアップを延々と取り続けるのではなく、バックアップコンテナがエラーで停止 | テスト済み |
| `BACKUP_KEEP=0` | 新しいものを含めて全バックアップを消すのではなく、バックアップを拒否 | テスト済み |
| `MC_VERSION=latest` で `PAPER_BUILD` を設定 | ビルドが停止: ビルド番号は具体的なバージョンでしか意味がない | テスト済み |
| `.env` を Windows の改行コードで保存 | `make` はバージョンを読むときに取り除くが、念のため `.env` は LF で保存すること | |
| `.env` を変えたのに `make restart` を実行 | 以前の設定のまま。`make restart` は `.env` を読み直さない。`make up` を使うこと。 | |
| アクセント記号、他の文字体系、絵文字を含む `MOTD` | `\uXXXX` のエスケープで書き込むので、どの Minecraft バージョンでも正しく表示される | テスト済み |
| `enable-status=false`（サーバーリストから隠す） | ヘルスチェックは RCON で確認し、サーバーは healthy のまま | テスト済み |
| `server.properties` で `server-ip` を設定 | 起動時に空に戻される。Docker 内のサーバーはすべてのインターフェースで待ち受ける必要があるため | |

## Minecraft のバージョン

| 状況 | 動作 | |
|---|---|---|
| `MC_VERSION` が存在しない（`9.9`） | `make` が停止: 利用不可、`make versions` を実行 | テスト済み |
| `MC_VERSION` が古すぎる（`1.16.5`） | `make` が停止: 1.17 以降をサポート | テスト済み |
| ベータ版の Paper ビルドしかないバージョン | `make` が停止: まだ安定版ビルドがない | |
| `latest` が新しい Minecraft リリースに移る | イメージを再ビルドしたときだけ起きる。驚かないよう `MC_VERSION` を固定すること。 | |
| `MC_VERSION` を上げた | ワールドをバックアップしてからアップグレード。プラグインは再解決 | テスト済み |
| `MC_VERSION` を下げた | 説明付きで起動を拒否（ダウングレード防止） | テスト済み |
| 新しいバージョンのバックアップを復元した | 次の起動時にダウングレード防止で拒否 | |
| Minecraft バージョンに対して `JAVA_VERSION` が古すぎる | `make` が必要な最低 Java を示して停止 | |
| 古い `MC_VERSION` で `docker compose up --build` を直接実行 | "Build with 'make up'" でビルドが停止。Compose を直接使うとデフォルトは Java 25 | |

## バックアップと復元

| 状況 | 動作 | |
|---|---|---|
| 手動バックアップと定期バックアップが同時に始まった | 順番に実行（共有ロック）されるので、バックアップ途中で自動保存が再開されることはない | テスト済み |
| ディスク容量が足りない | サイズをメッセージに示してバックアップを拒否。サーバーは安全に動き続ける | テスト済み |
| バックアップが中断された（コンテナが強制終了） | 隠しファイルの `.partial` だけが残り、次のバックアップが削除する。完成したバックアップが中途半端になることはない。 | |
| 書き込んだあとアーカイブが壊れていた | `gzip -t` で検出して破棄し、古いバックアップは残す | |
| 同じ秒に 2 つのバックアップ | 上書きせず、2 つ目に一意の接尾辞を付ける | |
| 定期バックアップ中にサーバーが停止 | 保存を止めずにバックアップを続行（書き込むものがない） | |
| ファイル名を間違えて `make restore` | 何にも手を付けずに停止。サーバーは動き続ける | テスト済み |
| 壊れたファイルで `make restore` | 何にも手を付けずに停止（`gzip -t`） | |
| 復元中に展開が失敗（ディスクがいっぱい） | 先に一時フォルダーに展開するので、現在のデータはそのまま | |
| なぜかサーバーがまだ動いている状態で復元 | 拒否 | |

## プラグイン

| 状況 | 動作 | |
|---|---|---|
| プラグインサイトでは Minecraft 対応とあるが、新しい Java が必要 | jar から検出し、動く中で最新のバージョンを使う | テスト済み |
| このサーバーで動くバージョンがない | 理由と `JAVA_VERSION` のヒントを示してスキップ。読み込めないインストール済みコピーは削除 | |
| 依存プラグインがサイトには書かれていないが `plugin.yml` にある | Hangar か Modrinth で名前から探し、jar のプラグイン名が一致したときだけ受け入れる | |
| 依存プラグインがどこにも見つからない | 名前を示して警告。サーバーは起動する | |
| 同じプラグインを Modrinth と Hangar の両方から指定 | 先のものを残し、後のものはスキップ。Paper が重複を見ることはない | |
| プラグインが手動でもインストールされている | 管理対象のコピーをスキップ | |
| プロジェクト名の入力ミス、または削除されたプロジェクト | 警告。ほかのプラグインには影響しない | テスト済み |
| 起動時に Modrinth や Hangar がダウンしている | 警告。インストール済みのバージョンは残り、次の起動で再試行 | |
| プラグインの更新が同時に 2 つ | 2 つ目は "already running" で拒否 | テスト済み |
| 準備済みプラグインの反映中にコンテナが停止 | 反映の手順は繰り返しても安全で、次の起動で完了する | |
| `plugins.txt` が BOM 付き、または Windows の改行コードで保存されている | 正しく処理される | |
| `plugins.txt` がない | プラグインはそのまま（何もアンインストールしない） | |
| `plugins.txt` の行をすべて削除 | 管理対象のプラグインはすべてアンインストール。手動で入れた jar は残る | |

## プレイヤーとモード

| 状況 | 動作 | |
|---|---|---|
| `Steve` がいるのに、オフラインのプレイヤーが `steve` で参加 | 拒否: "already taken, log in as exactly Steve" | テスト済み |
| スペース、ハイフン、アクセント記号、ドットを含むオフラインの名前 | ルールを説明して拒否 | テスト済み |
| 既存プレイヤーがいる状態でオンライン → オフライン | バックアップのあと、データをオフライン ID に移す | テスト済み |
| オフライン → オンラインで、プレイヤーにアカウントがない | 後で戻すときのために、データはオフライン ID のまま残す | テスト済み |
| Mojang に接続できない状態でオフライン → オンライン | サーバーは起動しない（データが分かれるのを防ぐ）。Docker が再試行 | |
| プレイヤーのデータが両方の ID にある | 新しいファイルを残し、古いほうは `player-migration-conflicts/` へ | テスト済み |
| Geyser/Floodgate 経由の統合版プレイヤー（`.Name`） | ユーザー名ルールで拒否。`ENFORCE_USERNAME_RULES=false` にすること | |

## 実行中

| 状況 | 動作 | |
|---|---|---|
| サーバープロセスがクラッシュ（`kill -9`） | Docker が再起動し、数秒で healthy に戻る | テスト済み |
| プロセスは生きているがサーバーがフリーズ | 約 5 分応答がなければウォッチドッグが再起動 | |
| 初回起動が非常に遅い（ワールド生成） | ウォッチドッグは最初の応答を待つ。ヘルスチェックは 5 分の猶予 | |
| Java のメモリ不足 | きれいに終了し、Docker が再起動 | |
| ゲーム内で `/stop` と入力 | 保存して停止し、Docker が再び起動（止めたままにするには `make down`） | |
| 非常に大きなワールドの保存が 2 分で終わらない | `STOP_TIMEOUT` を増やす | |
| ホストのポート 25565 がすでに使われている | `make up` が "port is already allocated" で失敗。`SERVER_PORT` を設定 | |
| ホストの再起動 | Docker が起動するとコンテナも戻る | |

## 既知の制限

- 対応しているのは、Paper 上の Minecraft: Java Edition 1.17 以降だけです。
- プラグインを自動で探すのは Modrinth と Hangar だけです。
- プラグインがプレイヤーの UUID ごとに保存しているデータは、オンラインモードとオフラインモードの間で移行されません。
- `make update-plugins`、`make backup`、`make console` は、サーバーコンテナが動いている必要があります。
- バージョンを決めるために、`make` は Docker で `eclipse-temurin:25-jdk` を（一度だけ）取得できる必要があります。
