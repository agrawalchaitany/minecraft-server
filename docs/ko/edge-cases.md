# <img src="../assets/icons/edge-cases.svg" width="28" height="28" alt=""> 예외 상황

특이한 상황에서 서버가 어떻게 동작하는지 정리했습니다. **테스트됨**으로 표시된 항목은 실제 서버에서 재현해 설명한 동작을 확인한 것입니다.

## 설정 실수

| 상황 | 동작 | |
|---|---|---|
| `EULA`가 `TRUE`가 아님 | 시작을 거부하고 동의하는 방법을 설명 | 테스트됨 |
| `RCON_PASSWORD`가 예시 값 그대로 | 시작을 거부 | 테스트됨 |
| `RCON_PASSWORD`에 백슬래시나 앞뒤 공백이 있음 | 시작을 거부. `server.properties`가 값을 조용히 바꿔 안전한 저장이 깨지기 때문. | 테스트됨 |
| `MEMORY=2GB`(잘못된 형식) | 시작을 거부: "must look like 2G or 1536M" | 테스트됨 |
| `MEMORY`가 `CONTAINER_MEMORY`가 허용하는 것보다 큼 | 메모리 부족 강제 종료 루프 대신, 시작을 거부하고 설정할 `CONTAINER_MEMORY`를 알려 줌 | 테스트됨 |
| `WATCHDOG_INTERVAL=1m` | 시작을 거부: 초 단위 정수여야 함 | 테스트됨 |
| 자동 업데이트가 켜진 상태에서 `PLUGIN_UPDATE_TIME=25:00` | 자동 업데이트가 조용히 안 도는 대신, 시작을 거부 | 테스트됨 |
| `BACKUP_INTERVAL=abc` | 쉬지 않고 백업하는 대신, 백업 컨테이너가 오류와 함께 멈춤 | 테스트됨 |
| `BACKUP_KEEP=0` | 새 백업을 포함해 모든 백업을 지우는 대신, 백업을 거부 | 테스트됨 |
| `MC_VERSION=latest`와 함께 `PAPER_BUILD` 설정 | 빌드 중단: 빌드 번호는 정확한 버전에서만 의미가 있음 | 테스트됨 |
| `.env`를 Windows 줄바꿈으로 저장 | `make`가 버전을 읽을 때 제거함. 안전하게 `.env`는 LF 줄바꿈으로 저장할 것 | |
| `.env`를 바꾸고 `make restart`를 실행 | 이전 설정이 유지됨. `make restart`는 `.env`를 다시 읽지 않음. `make up`을 쓸 것. | |
| 악센트, 다른 문자 체계, 이모지가 들어간 `MOTD` | `\uXXXX` 이스케이프로 기록해 모든 Minecraft 버전에서 올바르게 보임 | 테스트됨 |
| `enable-status=false`(서버 목록에서 숨김) | 헬스 체크가 RCON으로 대신 확인하고, 서버는 healthy 유지 | 테스트됨 |
| `server.properties`에 `server-ip` 설정 | 시작할 때 비워짐. Docker 안의 서버는 모든 인터페이스에서 수신해야 하기 때문 | |

## Minecraft 버전

| 상황 | 동작 | |
|---|---|---|
| `MC_VERSION`이 존재하지 않음(`9.9`) | `make`가 멈춤: 사용할 수 없음, `make versions`를 실행할 것 | 테스트됨 |
| `MC_VERSION`이 너무 오래됨(`1.16.5`) | `make`가 멈춤: 1.17 이상을 지원 | 테스트됨 |
| 베타 Paper 빌드만 있는 버전 | `make`가 멈춤: 아직 안정 빌드가 없음 | |
| `latest`가 새 Minecraft 릴리스로 넘어감 | 이미지를 다시 빌드할 때만 일어남. 예상치 못한 변화를 피하려면 `MC_VERSION`을 고정할 것. | |
| `MC_VERSION`을 올림 | 월드를 백업한 다음 업그레이드. 플러그인은 다시 결정 | 테스트됨 |
| `MC_VERSION`을 낮춤 | 안내와 함께 시작을 거부(다운그레이드 방지) | 테스트됨 |
| 더 새로운 버전의 백업을 복원함 | 다음 시작 때 다운그레이드 방지가 거부 | |
| Minecraft 버전에 비해 `JAVA_VERSION`이 너무 오래됨 | `make`가 필요한 최소 Java를 알려 주고 멈춤 | |
| 오래된 `MC_VERSION`으로 `docker compose up --build`를 직접 실행 | "Build with 'make up'"과 함께 빌드가 멈춤. Compose를 직접 쓰면 기본값이 Java 25 | |

## 백업과 복원

| 상황 | 동작 | |
|---|---|---|
| 수동 백업과 정기 백업이 같은 순간에 시작 | 하나씩 차례로 실행(공유 잠금)되므로, 백업 도중 자동 저장이 다시 켜지는 일이 없음 | 테스트됨 |
| 디스크 공간 부족 | 메시지에 크기를 알려 주고 백업을 거부. 서버는 안전하게 계속 실행 | 테스트됨 |
| 백업이 중단됨(컨테이너 강제 종료) | 숨김 `.partial` 파일만 남고, 다음 백업이 지움. 완료된 백업이 반쯤 된 상태인 일은 없음. | |
| 기록 후 아카이브가 손상됨 | `gzip -t`가 감지해 버리고, 이전 백업은 유지 | |
| 같은 초에 백업 두 개 | 덮어쓰지 않고 두 번째에 고유한 접미사를 붙임 | |
| 정기 백업 중 서버가 멈춤 | 저장을 멈추지 않고 백업을 계속(기록 중인 것이 없음) | |
| 파일 이름을 잘못 입력하고 `make restore` | 아무것도 건드리기 전에 멈춤. 서버는 계속 실행 | 테스트됨 |
| 손상된 파일로 `make restore` | 아무것도 건드리기 전에 멈춤(`gzip -t`) | |
| 복원 중 압축 풀기 실패(디스크 가득 참) | 먼저 임시 폴더에 풀기 때문에 현재 데이터는 그대로 | |
| 어떤 이유로 서버가 아직 실행 중인데 복원 | 거부 | |

## 플러그인

| 상황 | 동작 | |
|---|---|---|
| 플러그인 사이트는 내 Minecraft를 지원한다고 하지만 더 새로운 Java가 필요한 버전 | jar에서 감지하고, 동작하는 버전 중 가장 최신을 사용 | 테스트됨 |
| 이 서버에서 동작하는 버전이 없음 | 이유와 `JAVA_VERSION` 힌트를 남기고 건너뜀. 로드할 수 없는 설치본은 제거 | |
| 의존성이 사이트에는 없지만 `plugin.yml`에 있음 | Hangar나 Modrinth에서 이름으로 찾고, jar의 플러그인 이름이 일치할 때만 받아들임 | |
| 의존성을 어디서도 찾을 수 없음 | 이름을 밝힌 경고. 서버는 그래도 시작 | |
| 같은 플러그인을 Modrinth와 Hangar 양쪽에서 지정 | 첫 번째를 유지하고 두 번째는 건너뜀. Paper가 중복을 보는 일이 없음 | |
| 플러그인을 직접도 설치함 | 관리되는 사본을 건너뜀 | |
| 프로젝트 이름 오타, 또는 삭제된 프로젝트 | 경고. 다른 플러그인은 영향 없음 | 테스트됨 |
| 시작할 때 Modrinth나 Hangar가 다운됨 | 경고. 설치된 버전은 유지되고, 다음 시작 때 다시 시도 | |
| 플러그인 업데이트 두 개가 동시에 | 두 번째는 "already running"으로 거부 | 테스트됨 |
| 준비된 플러그인을 적용하는 중 컨테이너가 멈춤 | 적용 단계는 반복해도 안전하며, 다음 시작 때 마무리됨 | |
| `plugins.txt`가 BOM이나 Windows 줄바꿈으로 저장됨 | 처리됨 | |
| `plugins.txt`가 없음 | 플러그인은 그대로 둠(아무것도 제거하지 않음) | |
| `plugins.txt`의 모든 줄을 지움 | 관리되는 플러그인은 모두 제거. 직접 설치한 jar는 남음 | |

## 플레이어와 모드

| 상황 | 동작 | |
|---|---|---|
| `Steve`가 있는데 오프라인 플레이어가 `steve`로 접속 | 거부: "already taken, log in as exactly Steve" | 테스트됨 |
| 공백, 대시, 악센트, 점이 들어간 오프라인 이름 | 규칙을 설명하며 거부 | 테스트됨 |
| 기존 플레이어가 있는 상태에서 온라인 → 오프라인 | 백업 후 데이터를 오프라인 ID로 옮김 | 테스트됨 |
| 오프라인 → 온라인, 플레이어에게 계정이 없음 | 나중에 다시 바꿀 때를 위해 데이터를 오프라인 ID 아래 유지 | 테스트됨 |
| Mojang에 연결할 수 없는 상태에서 오프라인 → 온라인 | 서버가 시작되지 않음(데이터가 나뉘는 것을 방지). Docker가 재시도 | |
| 플레이어 데이터가 두 ID 모두에 있음 | 더 새로운 파일을 유지하고, 오래된 것은 `player-migration-conflicts/`로 | 테스트됨 |
| Geyser/Floodgate를 통한 Bedrock 플레이어(`.Name`) | 사용자 이름 규칙에 의해 거부. `ENFORCE_USERNAME_RULES=false`로 설정할 것 | |

## 실행 중

| 상황 | 동작 | |
|---|---|---|
| 서버 프로세스 크래시(`kill -9`) | Docker가 재시작하고, 몇 초 안에 다시 healthy | 테스트됨 |
| 프로세스는 살아 있는데 서버가 멈춤 | 약 5분 동안 응답이 없으면 워치독이 재시작 | |
| 아주 느린 첫 시작(월드 생성) | 워치독은 첫 응답을 기다림. 헬스 체크는 5분의 여유 | |
| Java 메모리 부족 | 깔끔하게 종료하고 Docker가 재시작 | |
| 게임에서 `/stop` 입력 | 저장하고 멈춤. Docker가 다시 시작(멈춘 채로 두려면 `make down`) | |
| 아주 큰 월드가 2분 안에 저장을 마치지 못함 | `STOP_TIMEOUT`을 늘릴 것 | |
| 호스트의 포트 25565가 이미 사용 중 | `make up`이 "port is already allocated"로 실패. `SERVER_PORT`를 설정 | |
| 호스트 재부팅 | Docker가 시작되면 컨테이너도 돌아옴 | |

## 알려진 한계

- Paper 위의 Minecraft: Java Edition 1.17 이상만 지원합니다.
- 플러그인은 Modrinth와 Hangar에서만 자동으로 찾습니다.
- 플러그인이 플레이어 UUID별로 저장한 데이터는 온라인과 오프라인 모드 사이에서 마이그레이션되지 않습니다.
- `make update-plugins`, `make backup`, `make console`은 서버 컨테이너가 실행 중이어야 합니다.
- 버전을 결정하려면 `make`가 Docker로 `eclipse-temurin:25-jdk`를 (한 번) 내려받을 수 있어야 합니다.
